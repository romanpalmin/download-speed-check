# download-speed-check

Консольный скрипт на Node.js (без зависимостей), который измеряет скорость скачивания: делает 10 запросов подряд к указанному адресу, каждый раз дожидается полного ответа и печатает среднее время запроса, общий объём скачанных данных и скорость.

## Требования

Node.js 20 или новее (встроенные `fetch` и `node:test`). Проверено на Node 24. Ничего устанавливать не нужно.

## Запуск

```bash
node src/cli.js <url>
```

Пример (тестовый файл 10 МБ, всего скачается около 100 МБ):

```bash
node src/cli.js "https://speed.cloudflare.com/__down?bytes=10000000"
```

Пример вывода:

```
Скачиваю https://speed.cloudflare.com/__down?bytes=10000000 10 раз подряд...
Запросов:       10
Среднее время:  7097.0 мс
Скачано всего:  100.00 МБ (100000000 байт)
Скорость:       11.27 Мбит/с
                1.41 МБ/с
```

Коды выхода: `0` успех, `1` ошибка запроса (сеть или HTTP-статус не 2xx), `2` адрес не указан или некорректен.

## Единицы измерения и формулы

- `1 МБ = 1 000 000 байт` (десятичные, не МиБ), `1 Мбит = 1 000 000 бит`. Интернет-провайдеры тоже считают в десятичных единицах, поэтому значение в Мбит/с сопоставимо со скоростью тарифа.
- Скорость в **МБ/с** = всего байт / 1 000 000 / всего секунд.
- Скорость в **Мбит/с** = МБ/с × 8.
- Скорость считается как **всего байт / всё время**, а не как среднее скоростей отдельных запросов: среднее завышало бы вес быстрых маленьких ответов.
- Среднее время = сумма времён запросов / 10. Время запроса идёт от отправки до получения **всего** тела ответа (`arrayBuffer()` завершается только когда тело прочитано целиком). Паузы между запросами не учитываются.

## Тесты

```bash
npm test        # node --test, встроенный раннер
```

Тесты поднимают локальный HTTP-сервер на случайном порту: интернет не нужен, размер ответа известен точно. Проверяются формулы агрегации, подсчёт байт, обработка статусов не 2xx, что запросов ровно 10 и они не пересекаются во времени, а также CLI как отдельный процесс (коды выхода 0/1/2 и вывод). Тесты проверены мутациями: если сломать формулу, число запросов, порядок или проверку статуса, тест падает.

## Устройство

- `src/measure.js` — логика (функции, которые удобно тестировать), `src/cli.js` — тонкая обёртка: аргументы, вывод, коды выхода.
- Запросы последовательные намеренно (`await` в цикле, без `Promise.all`): параллельные измеряли бы пропускную способность всего канала, а не скачивание, и результаты были бы несопоставимы.
- Реализация `fetch` передаётся параметром, поэтому в тестах её легко подменить.

## Ограничения и что улучшил бы

- В результат входят DNS, TLS-рукопожатие и ожидание первого байта, поэтому на маленьких файлах скрипт показывает скорее задержку, чем пропускную способность. Разделение времени на ожидание первого байта и собственно скачивание дало бы чище число.
- Число запросов и таймаут сейчас зашиты: естественно добавить флаги `--count`, `--timeout`, `--json`.
- Выводить время каждого запроса, минимум, максимум и медиану.
- Читать тело потоком и считать чанки вместо `arrayBuffer()`, чтобы не держать большой файл в памяти.
- Прогревочный запрос, который не учитывается (переиспользование соединения, кэши).
